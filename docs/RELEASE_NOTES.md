## 1. Headline

The platform is live: infrastructure is provisioned from code, merges to `main` deploy themselves,
and a failed release reverses itself. The API is reachable only through an ALB, with PostgreSQL and
Redis isolated behind security-group references in subnets that have no route to the internet.

---

## 2. What shipped

### Infrastructure as code

- Three-tier VPC across 3 availability zones: public (ALB/NAT), private (ECS), isolated (data).
- ECS Fargate cluster with Container Insights, 2 baseline tasks, autoscaling to 10 on CPU (70%) and
  ALB request count per target (1000).
- Application Load Balancer with health-check-aware rolling updates, access logs to an encrypted,
  lifecycle-managed S3 bucket, HTTP→HTTPS redirect when a certificate is configured.
- RDS PostgreSQL 16, Multi-AZ, encrypted gp3 storage that autogrows 50 → 200 GiB, 30-day automated
  backups, Performance Insights, slow-query logging.
- ElastiCache Redis 7 with two nodes, automatic failover, TLS, auth token, at-rest encryption.
- ECR repository with immutable tags, scan-on-push and a lifecycle policy that keeps 50 releases.
- Interface VPC endpoints for ECR, CloudWatch Logs and Secrets Manager, plus an S3 gateway endpoint.
- Terraform remote state in versioned, encrypted S3 with DynamoDB locking.

### Application

- Node.js 24 API with dependency-injected Express app, structured JSON logging, Prometheus metrics,
  pooled Postgres access and a Redis cache-aside helper.
- `/health` (dependency free), `/ready` (dependency aware) and `/metrics`.
- Fail-fast configuration validation (exit code 78) so a misconfigured task never half-boots.
- SIGTERM handler that flips readiness to 503, drains in-flight requests and exits cleanly inside the
  30-second ECS stop timeout.
- Multi-stage, non-root container image; production dependencies only in the runtime layer.

### Delivery pipeline

- **CI (PR + main):** tests on Node 22 and 24, ESLint, `audit-ci --high`, Trivy filesystem scan
  (vulnerabilities, secrets, misconfiguration), Terraform `fmt`/`validate`, image build and scan, and
  a runtime smoke test against real Postgres and Redis including a graceful-shutdown assertion.
- **Deploy (merge to main):** OIDC role assumption, immutable image push tagged with the Git SHA,
  live task definition export, rendered revision, rolling update with `wait-for-service-stability`,
  ALB smoke test, and automatic rollback to the previously recorded revision on failure.
- **Rollback (manual):** one-click workflow with an optional explicit revision and a required reason
  that is written to the run summary.
- **Terraform (PR + manual):** plan on pull requests, apply behind the `production` environment.

### Security

- No AWS access keys: GitHub Actions federates via OIDC, and the trust policy is scoped to this
  repository, the `main` branch and the production environment.
- No secrets in source: RDS and Redis credentials are generated by Terraform, stored in Secrets
  Manager and injected into the container at runtime.
- Data tier unreachable from the internet and from the public subnet.
- Encryption in transit (TLS listener, `sslmode=require`, `rediss://`) and at rest (RDS, ElastiCache,
  SNS, S3 state and access logs).

### Operations

- CloudWatch alarms: ALB 5XX ratio > 5% per 5 minutes, unhealthy targets, ECS CPU > 85%, ECS memory
  > 85%, RDS CPU > 80%, RDS free storage < 10 GiB. Every alarm has an OK action.
- Dashboard covering requests vs 5XX, latency percentiles, ECS CPU/memory and RDS CPU/connections.
- Runbook, maintenance log and this release note.

## 4. Known limitations

| # | Limitation | Impact | Plan |
| --- | --- | --- | --- |
| 1 | Schema migration is a manual one-off ECS task (`npm run migrate`), not yet a pipeline stage | Schema drift if skipped | v1.1.0 pre-deploy migration task |
| 2 | No WAF or rate limiting at the edge | Abuse traffic reaches the app | v1.1.0 AWS WAF managed rules |

## 5. Upgrade / first-deploy procedure

1. `AWS_PROFILE=... ./scripts/bootstrap-aws.sh` → writes `terraform/backend.hcl`.
2. Populate `terraform/envs/prod.tfvars` (certificate ARN, alert email, state bucket/table).
3. `terraform init -backend-config=backend.hcl && terraform apply -var-file=envs/prod.tfvars`.
4. Set repository variables: `AWS_DEPLOY_ROLE_ARN`, `ECR_REPOSITORY`, `ECS_CLUSTER`, `ECS_SERVICE`,
   `ALB_URL`, `AWS_REGION`, `TF_STATE_BUCKET`, `TF_STATE_LOCK_TABLE`.
5. Create the `production` environment with required reviewers.
6. Merge to `main`; the first run replaces the bootstrap placeholder image.
7. Confirm alarms in `ALARM`/`OK` state and that SNS delivery reaches the on-call channel.

**No database migration is destructive in this release.** The only schema change is an idempotent
`CREATE TABLE IF NOT EXISTS items` plus an index.

## 6. Rollback

- Automatic: any failure after `update-service` (stability wait, smoke test) restores the recorded
  previous task definition.
- Manual: **Actions → Rollback → Run workflow**, leave the revision empty for the previous active
  revision, or paste a specific task definition ARN.
- CLI: `CLUSTER=... SERVICE=... ./scripts/rollback.sh`.

Expected recovery time: under 10 minutes, dominated by ECS task replacement and target health checks.
